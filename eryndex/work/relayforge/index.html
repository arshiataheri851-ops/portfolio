RelayForge

A webhook delivery engine with durable event state, signed payloads and controlled outbound HTTPS delivery.

Implemented capabilities

  • SQLite-backed event and subscription persistence with a transactional outbox
  • Idempotent event ingestion and stable delivery identifiers
  • HMAC-SHA256 signatures with timestamp and delivery-ID headers
  • Exact-host allowlisting and DNS-pinned outbound connections
  • HTTPS-only delivery, redirects disabled and bounded timeouts
  • Optional worker, exponential retry backoff, leases, attempt history and dead-letter redrive
  • Separate producer and operator authentication tokens

Architecture

Authenticated event intake → transactional persistence/outbox → subscription routing → signed HTTPS delivery → retry and dead-letter lifecycle.

Delivery semantics and boundaries

RelayForge provides at-least-once delivery attempts, not exactly-once delivery. A remote receiver should deduplicate using the stable delivery ID. SQLite is a durable single-node store, not a distributed queue.

The source repository calls for network egress controls, secret management, monitoring, backup/restore drills and operational review. No production traffic, independent security audit, customer deployment or service-level guarantee is claimed.
